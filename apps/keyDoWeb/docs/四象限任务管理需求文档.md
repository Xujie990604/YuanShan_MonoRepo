# 四象限任务管理功能需求文档

## 📋 项目概述

在 keyDoWeb 首页实现一个基于**艾森豪威尔矩阵（Eisenhower Matrix）**的任务管理系统，采用 2×2 四象限布局，支持任务拖拽功能。

**参考应用：** 滴答清单（TickTick）

## 🎯 核心功能需求

### 1. 四象限布局

#### 1.1 象限定义（✅ 已确认：使用 Q1-Q4）
- **象限 Q1（重要且紧急）**：左上角
- **象限 Q2（重要不紧急）**：右上角
- **象限 Q3（不重要但紧急）**：左下角
- **象限 Q4（不重要不紧急）**：右下角

#### 1.2 布局要求
- 2×2 网格布局，每个象限占据相等的空间
- 每个象限有独立的背景色（用于视觉区分）
- 每个象限显示标题和任务数量
- 空象限显示"暂无任务"提示文字（✅ 已确认）
- 暂不考虑移动端响应式（✅ 已确认）

### 2. 任务管理

#### 2.1 任务数据结构
```typescript
interface Task {
  id: string;              // 唯一标识
  title: string;           // 任务标题
  quadrant: QuadrantType;  // 所属象限：'Q1' | 'Q2' | 'Q3' | 'Q4'
  completed: boolean;      // 是否完成
  createdAt: string;       // 创建时间
  updatedAt: string;       // 更新时间
  // 可选字段（未来扩展）
  dueDate?: string;        // 截止日期
  priority?: 'low' | 'medium' | 'high';  // 优先级
  tags?: string[];         // 标签
  description?: string;    // 描述
}
```

#### 2.2 任务显示
- 每个任务显示为卡片形式
- 显示任务标题
- 显示完成状态（复选框）
- 支持任务完成/取消完成
- 支持任务删除（待确认交互方式）

#### 2.3 任务分组
- 按完成状态分组：未完成任务、已完成任务
- 已完成任务默认不折叠（✅ 已确认）
- 显示各分组的任务数量

### 3. 拖拽功能

#### 3.1 拖拽范围
- 任务可以**跨象限**拖拽（改变象限归属）
- 暂不考虑象限内任务排序（✅ 已确认）

#### 3.2 拖拽交互
- 拖拽时显示视觉反馈（拖拽中的任务样式变化）
- 拖拽目标区域高亮显示
- 拖拽完成后更新任务状态
- 支持拖拽动画效果

#### 3.3 技术实现
- 使用 **@dnd-kit/core** 作为核心库
- 使用 **@dnd-kit/sortable** 实现排序
- 使用 **@dnd-kit/utilities** 工具函数

### 4. 左侧工具栏

#### 4.1 当前功能
- 显示用户头像（Avatar）
- 头像可点击（功能待定：个人设置？）

#### 4.2 未来扩展（预留）
- 导航菜单
- 设置入口
- 搜索功能
- 其他快捷操作

## 🔄 核心交互流程

1. **页面加载**：从数据源加载任务，按象限和完成状态分组显示
2. **添加任务**：点击象限右上角 `+` 按钮，输入标题后添加到对应象限
3. **完成任务**：点击复选框或标题切换完成状态
4. **拖拽任务**：拖拽任务卡片到目标象限，更新任务象限
5. **删除任务**：右键菜单删除任务

## 🔌 服务端接口需求（✅ 已确认）

### 1. API 接口设计原则

#### 1.1 RESTful 规范（✅ 已确认）
- 使用标准 HTTP 方法（GET、POST、PUT、DELETE）
- 接口前缀：`/api/v1/`（✅ 已确认）
- 资源路径清晰明确
- 状态码使用规范

#### 1.2 认证授权（✅ 已确认）
- JWT Token 认证（✅ 已确认）
- 任务数据按用户隔离
- 所有任务管理接口需要携带认证信息

#### 1.3 数据格式
- 请求/响应统一使用 JSON
- 时间格式：ISO 8601（`2025-01-15T10:00:00Z`）
- 错误信息统一格式

#### 1.4 其他限制（✅ 已确认）
- ❌ 不支持分页（MVP 阶段数据量不大）
- ❌ 不需要批量操作接口
- ❌ 不需要 WebSocket 实时同步
- ❌ 不需要多设备同步
- ❌ 不支持任务编辑
- ✅ 支持象限内任务排序（使用 lexorank 算法）

### 2. 接口列表（✅ 已确认）

#### 2.1 获取任务列表
```
GET /api/v1/tasks
认证：需要 JWT Token
功能：获取当前用户的所有任务
响应：Task[]
```

#### 2.2 创建任务
```
POST /api/v1/tasks
认证：需要 JWT Token
功能：创建新任务
请求体：{ title: string, quadrant: QuadrantType, order?: string }
响应：Task
说明：order 字段可选，如果不提供则由服务端计算（lexorank）
```

#### 2.3 更新任务
```
PUT /api/v1/tasks/:id
认证：需要 JWT Token
功能：更新任务（象限、完成状态、排序等）
请求体：{ title?: string, quadrant?: QuadrantType, completed?: boolean, order?: string }
响应：Task
说明：支持部分更新，order 字段用于象限内排序
```

#### 2.4 删除任务
```
DELETE /api/v1/tasks/:id
认证：需要 JWT Token
功能：删除任务（硬删除）
响应：{ success: boolean }
说明：不支持软删除（✅ 已确认）
```

### 3. 数据模型（✅ 已确认）

#### 3.1 数据库字段
- `id`: 主键（UUID 或自增 ID）
- `user_id`: 用户 ID（外键）
- `title`: 任务标题
- `quadrant`: 象限类型（Q1/Q2/Q3/Q4）
- `completed`: 是否完成（boolean）
- `order`: 排序字段（lexorank 字符串，用于象限内排序）✅ 已确认
- `created_at`: 创建时间
- `updated_at`: 更新时间

#### 3.2 字段说明
- **order 字段**：使用 lexorank 算法计算排序值，字符串类型
  - 用于同一象限内任务的排序
  - 插入新任务时，如果不指定 order，服务端自动计算
  - 拖拽排序时，前端需要计算新的 order 值并传递给服务端

#### 3.3 扩展字段（未来）
- `due_date`: 截止日期
- `priority`: 优先级
- `tags`: 标签（JSON 数组）
- `description`: 描述

### 4. 类型定义规范（✅ 已确认）

#### 4.1 共享类型管理
- ✅ 所有前后端共享的类型定义在 `@yuan-shan/keydo-contract` 包中
- ✅ 包括：Task、QuadrantType、创建/更新任务的请求/响应类型
- ✅ 前端项目中的 `src/types/task.ts` 需要迁移到 `keyDoContract`
- ✅ 使用 Zod Schema 进行数据验证

#### 4.2 需要在 keyDoContract 中定义的类型
```typescript
// 需要在 keyDoContract 中定义

  quadrant: QuadrantType;
  completed: boolean;
  order: string;  // lexorank 排序值
  createdAt: string;  // ISO 8601

// 创建任务请求

}

// 更新任务请求

  title?: string;
  quadrant?: QuadrantType;
  completed?: boolean;
  order?: string;  // 用于排序
}
```
