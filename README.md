# YuanShan_Monorepo

## 一、项目架构

### 1.1 传统化架构

组件库、用户中心、脚手架、图表库、工具库

- 独立项目结构，所有的项目都是分开的 git 仓库
- 技术栈独立
- 规范化、自动化相关处理每个项目之间都是割裂的
- 依赖管理、版本控制很难统一管理
- 部署、docker、CI/CD 等很难形成统一

### 1.2 Monorepo

- 混合项目结构，所有的工程形成子包管理
- 技术栈高度统一（团队基建、业务项目、子服务、技术栈）
- 规范化、自动化、流程化项目间共享
- 依赖管理、版本控制高度统一
- 部署、docker、CI/CD 等统一部署流程

### 1.3 传统架构到 monorepo 架构演进

- 阶段 1：传统架构基础痛点（主要矛盾）
  - 代码需要集中化，将多个关联项目统一到一个 git 仓库
  - 工具引入，pnpm workspace
  - CI/CD 重构
- 阶段 2：具体的 Monorepo 架构
  - 公共模块抽离
  - pnpm、turbo 解决主包和子包的关系
- 阶段 3：自动化构建流程优化
  - 打包方案，`vite(业务代码推荐)`、webpack、rollup、`tsup（组件库推荐）`、esbuild、swc
  - 构建流程优化，依赖关系、哪些包需要前置构建
  - 发布，npm publish、docker
  - 监控和测试

### 1.4 关键性卡点(步骤)

1. 项目统一
2. pnpm 配置
3. 依赖管理
4. 统一化脚本
   - 工程化脚本：package.json 中的 script
   - script 脚本

## 二、基于 monorepo 架构的实践经验

- 组件库：工具库、图表库
- 脚手架：基建类形态的项目模块
- 业务系统
- 服务端架构(全栈项目)
