# 任务详情字段（description）服务端改动说明

## 📋 改动概述

在 Task 模型中新增 `description` 字段，用于存储任务详情信息。

---

## 🔧 需要修改的文件

### 1. Prisma Schema

**文件：`prisma/schema.prisma`**

在 `Task` 模型中添加 `description` 字段：

```prisma
model Task {
  id          String   @id @default(uuid())
  userId      Int      @map("user_id")
  title       String   @db.VarChar(255)
  description String?  @db.Text // 新增：任务详情（可选，可为 NULL）
  quadrant    String   @db.VarChar(2) // Q1, Q2, Q3, Q4
  completed   Boolean  @default(false)
  order       String   @db.VarChar(255) // lexorank 排序值
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, quadrant])
  @@index([userId, order])
  @@map("tasks")
}
```

**字段说明：**
- `description String?` - 可选字段，可为 NULL
- `@db.Text` - 使用 TEXT 类型，支持长文本

---

### 2. 数据库 Migration

**执行命令：**

```bash
cd server/keyDoServer
pnpm prisma migrate dev --name add_task_description
```

这会：
1. 创建 migration 文件
2. 在数据库中添加 `description` 列（可为 NULL）
3. 重新生成 Prisma Client

**Migration SQL 示例：**

```sql
-- AlterTable
ALTER TABLE "tasks" ADD COLUMN "description" TEXT;
```

## ⚠️ 注意事项

### 1. 数据库兼容性

- 字段设为可选（`String?`），对已有数据无影响
- 已有任务的 `description` 为 `NULL`，前端会显示为 `undefined`

### 2. 类型一致性

- 服务端使用 `@yuan-shan/keydo-contract` 包中的类型定义
- 前端和服务端共享相同的类型，确保类型一致

### 3. Migration 执行顺序

1. 先修改 Prisma Schema
2. 执行 `pnpm prisma migrate dev`
3. 重新生成 Prisma Client（migration 会自动执行）
4. 修改 TaskService 代码

### 4. 测试建议

- 创建任务时传入 `description`，验证保存成功
- 更新任务时修改 `description`，验证更新成功
- 查询任务时验证 `description` 字段正确返回
- 测试 `description` 为 `null` 的情况（已有任务）
